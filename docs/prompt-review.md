# 프롬프트 역할 분리 점검 목록

원칙(브리프 §6): 모델은 자연어 해석(파서, LoRA-A)과 문장 만들기(생성기, LoRA-B)만 한다. 판단은 코드(turn-engine)가 한다. 프롬프트 템플릿을 새로 만들거나 고칠 때(새 `prompt_template_version`) 아래를 확인하고 결과를 이 파일 끝의 표에 적는다.

## 공통
- [ ] 입력 계약에 없는 정보를 프롬프트에 넣지 않았다(시각, 환자 정보, 이전 턴 원문 등).
- [ ] 출력 형식 지시는 "해당 출력 계약 JSON 하나"뿐이고, 스키마의 필드 의미를 프롬프트에서 새로 정의하지 않았다.
- [ ] 예시(few-shot)를 넣었다면 실제 환자 발화가 아니고, 입력·출력이 계약 스키마를 통과한다.
- [ ] 같은 입력은 항상 같은 문자열이 된다(결정적 직렬화, 시각·난수 없음).
- [ ] 템플릿을 고쳤다면 새 버전 이름을 붙였고 골든 파일(`tests/examples/*.prompt-N.txt`)을 새로 만들었다. 기존 버전의 출력은 바꾸지 않았다.

## 파서(LORA_A): 해석만
- [ ] 발화에 있는 내용을 항목으로 옮기라고만 한다. 값이 임상적으로 맞는지, 범위 안인지 판단하라고 하지 않는다(정규화·검증은 Answer Normalizer).
- [ ] 이미 저장된 값과 같은지/다른지, 정정인지 충돌인지의 **최종 판정**을 요구하지 않는다(Answer Judge). 스키마가 모델에게 맡긴 표지(`CORRECTION_MARKED` 등 `Intent`)를 발화에서 읽어 내는 것은 해석이다.
- [ ] 저장 여부·다음 질문·종료 여부를 정하라고 하지 않는다(Record Writer, Dialogue Planner).
- [ ] 위험 신호(`RISK_SIGNAL`)는 발화에 나타난 표현을 표지하는 것까지이고, 조치(알림, 중단)를 지시하지 않는다.
- [ ] `source_text`와 `evidence`는 발화에서 그대로 가져오라고 한다(요약·교정 금지).

## 생성기(LORA_B): 문장만
- [ ] 응답 지시(`Directive`)의 `action`과 `sentence_materials`를 문장으로 옮기라고만 한다. 무엇을 물을지, 문항을 건너뛸지는 정하지 않는다.
- [ ] 지시에 없는 의학 정보·조언·진단·안심시키는 말을 추가하지 말라고 한다.
- [ ] `fixed_sentences`는 그대로 쓰도록 한다(바꾸지 않는다).
- [ ] 값(`say_values`)은 지시에 있는 것만 말하고 계산·단위 변환을 하지 않는다.
- [x] 프롬프트에 `is_fallback`을 쓰지 않는다. 모델은 `response_text`만 낸다. `is_fallback`은 코드가 채운다(D36, 헤드 확인).
