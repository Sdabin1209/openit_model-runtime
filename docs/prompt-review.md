# 프롬프트 역할 분리 점검 목록

원칙(브리프 §6): 모델은 자연어 해석과 문장 만들기만 한다. 판단은 코드가 한다.
2.0.0(D74, D75)부터 이 리포지토리는 **시스템 프롬프트의 문장을 갖지 않는다.** 시스템 프롬프트는 모델 패키지(어댑터 디렉터리의 파일, `ModelPackageManifest.system_prompt`)의 일부이고 학습과 짝이다. 이 리포지토리의 프롬프트 템플릿 버전(`prompt-4`; `prompt-3`은 0.7.0에서 제거)은 **조립 규칙**(채팅 형식, 입력 JSON 직렬화)뿐이다. 그래서 아래 점검은 템플릿의 조립 규칙에 대한 것이고, 프롬프트 문장의 역할 분리 검토는 패키지를 만드는 model-lab의 몫이다.

## 템플릿(조립 규칙)을 새로 만들거나 고칠 때
- [ ] 코드에 시스템 프롬프트 문장을 넣지 않았다(패키지의 것만 쓴다).
- [ ] 입력 JSON 외의 정보를 사용자 메시지에 넣지 않았다(시각, 환자 정보, 이전 턴 원문 등).
- [ ] 같은 입력과 같은 시스템 프롬프트는 항상 같은 문자열이 된다(결정적 직렬화, 시각·난수 없음).
- [ ] 학습의 채팅 템플릿과 같다(Qwen3, `enable_thinking=False`). **확인 방법: 실제 토크나이저의 `apply_chat_template` 결과와 바이트 비교(아직 못 함).**
- [ ] 학습 데이터 user 메시지의 입력 JSON 직렬화와 같다. **확인 방법: 학습 데이터의 user 메시지와 비교(이 영역은 학습 서버 데이터를 읽을 수 없어 못 함).**
- [ ] 템플릿을 고쳤다면 새 버전 이름을 붙였고 골든 파일(`tests/prompt_golden/*.prompt-N.txt`)을 새로 만들었다. 기존 버전의 출력은 바꾸지 않았다.
