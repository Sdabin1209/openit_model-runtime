# ADR 0036: 모방(mimic) 추출기는 부정형 칸의 값을 칸 이름의 뜻으로 뒤집는다

## 상태
채택(2026-11-08, 헤드 지시: 데모 결함). [ADR 0018](0018-mimic-components.md)을 보완한다.

## 맥락
모방 추출기는 boolean 칸 값을 발화의 예/아니오 낱말로 정했다. 칸 `Q7.does_not_drink`(마시지 않는다)에 "네 안 마셔요"는 False, "네 마십니다"는 True로 나갔다. 발화의 극성은 행위(마신다)의 것이고, 칸 값은 칸 이름의 뜻(마시지 않는다)이다. 그래서 환자가 "안 마셔요"라고 했는데 데모는 "마신다"로 기록했다. 배포 쪽 흐름 파일에는 값 해석 규칙이 없다(헤드 확인), 원인은 이 추출기다.

## 결정
boolean 칸의 키 끝 조각(`문항.칸`의 칸 이름)을 밑줄로 나눠 부정 낱말(`not`, `no`, `never`, `non`; 규칙표 `extractor.negated_slot_tokens`)이 하나라도 있으면, 발화에서 읽은 값을 뒤집어 낸다(`does_not_drink`, `no_smoking`). 뒤집은 값이 저장·정정 비교·건너뛰기 규칙에 모두 쓰인다. 읽는 규칙(예/아니오 낱말)은 넓히지 않는다. 정수 칸은 건드리지 않는다.

## 왜
- 계약 `QuestionFieldSpec`(v4.0.5)에는 극성 정보가 없다(slot, data_type, unit, 범위, options, repeat_keys뿐). 칸 규격에 있었다면 그것을 썼을 것이다. 없으므로 칸 이름 낱말에 기댄다. 근거: 데이터셋·문진 스키마의 칸 이름이 `does_not_drink`처럼 부정을 이름에 담는다(deploy 흐름 파일의 건너뛰기 규칙 `Q7.does_not_drink == true`가 "안 마심이면 Q7_1 건너뜀"으로 같은 뜻을 쓴다).
- 낱말은 코드가 아니라 규칙표 데이터에 둔다(ADR 0018과 같은 이유). 밑줄 조각 단위로 맞춰 `nothing_found`의 `no` 같은 부분 문자열 오판을 피한다.
- 모방은 시험 대역이라 자연어 이해를 넓히지 않고 극성만 고친다.

## 검토한 대안과 버리는 이유
- 발화 낱말에서 "마시지 않" 등을 칸 뜻과 맞춰 해석: 모방의 이해 범위를 넓힌다. 기각.
- 계약에 극성 필드 추가 요청: 운영 모델(LoRA-A)은 학습 데이터에서 칸 뜻을 배우므로 계약 변경이 필요 없고, 이 결함은 대역에만 있다. 지금은 요청하지 않는다.

## 결과
얻는 것: 부정형 칸에서 "안 마셔요"가 True(마시지 않는다)로 나가고 건너뛰기 규칙이 맞게 선다. 감수하는 것: 칸 이름에 부정 낱말이 없이 뜻만 부정인 칸(예: `abstains`)은 뒤집지 못한다. 이중 부정 칸은 한 번만 뒤집는다. 실제 문진 스키마의 모든 boolean 칸 이름을 점검하지는 않았다.

## 되돌리는 조건
계약 칸 규격에 극성 필드가 생기면 이름 낱말 규칙을 그 필드로 바꾼다. 데모가 진짜 모델로 대체되면 모방과 함께 지운다.
