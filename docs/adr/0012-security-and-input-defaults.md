# ADR 0012: 보안 기본값과 입력·연결 한도

## 상태
채택(0.7.3, 감사 MR-1/2/3/4/9/10/14).

## 맥락
감사에서 다음이 지적됐다: 토큰이 없으면 모두 허용(인증 기본 열림), 빈 토큰 허용, 기본 바인드 0.0.0.0, 입력 길이 상한 없음, 엔진의 입력 거부가 `/readyz`를 503으로 고정, 연결·스레드·동시 적재 한도 없음, 깊은 중첩 JSON·비정상 Content-Length 미처리, 비인증 `/readyz`의 내부 정보 노출, 특수 토큰, 번들 디렉터리 미정리.

## 결정
- 인증은 기본 닫힘: 토큰이 없으면 시작 거부(개발용 `MODEL_RUNTIME_ALLOW_NO_AUTH=1`만 예외), 빈 역할·빈 토큰·중복은 시작 거부, 토큰은 `hmac.compare_digest`로 비교, 기본 바인드 127.0.0.1(이미지는 `MODEL_RUNTIME_HOST=0.0.0.0`). 역할 `loader`는 적재 PUT만 가능(extract/respond 불가), `MODEL_RUNTIME_PUT_ROLES`를 주면 PUT 가능한 역할을 제한한다(기본: 인증된 모든 역할 — survey-service가 404에서 PUT으로 다시 적재하기 때문).
- 비인증 `/readyz` 503은 사유를 숨기고, 인증된 호출에만 사유를 준다. `/healthz`는 의존과 무관하게 200(FAULT_POLICY 5).
- 입력 길이: JSON 직렬화(비ASCII 그대로) 2500자 초과는 400. 엔진이 입력을 `ValueError`로 거부해도 400이고 `/readyz`는 그대로(엔진 사망은 다른 예외로 구분해 503).
- 연결: 소켓 timeout 15s, 동시 연결 32(넘으면 503으로 닫음), 동시 적재 2, 보존하는 실패 릴리스 항목 16, 본문 4MiB, `Content-Length` 비정상·`Transfer-Encoding`은 400, 깊은 JSON은 400.
- 입력 문자열의 채팅 특수 토큰 모양을 깬다(ADR 0011).
- 우아한 종료: SIGTERM에서 새 연결을 그만 받고 진행 중 요청을 최대 5s 기다린 뒤 엔진을 내린다.

## 왜 (따른 표준과 근거)
표준: 인증 기본 거부·상수 시간 비교·최소 노출은 일반적인 보안 관행이고, 비밀은 파일로(D84). 값의 출처: **2500자**는 `gpu-12g`의 `max_model_len` 4096 토큰에서 출력 `max_tokens` 512와 시스템 프롬프트·틀 여유(시스템 프롬프트 길이는 패키지마다 달라 측정하지 않았고 약 1000토큰으로 가정)를 빼고, 보수적으로 문자 1개가 토큰 1개 이하라고 가정해 정한 추정이다(**실제 토큰 수 측정 안 함**). **15s, 32, 2, 16, 5s**는 측정·표준에서 나온 값이 아니다: 엔진이 직렬이라 32 연결이 넘어도 대기만 길어진다는 판단(ADR 0005), 적재는 GPU 메모리를 쓰는 무거운 작업이라 2, 나머지는 **근거 기록 없음(초기값)**이다.

## 검토한 대안과 버리는 이유
- 인증 기본 열림 유지: 감사가 지적한 위험. 기각. 
- PUT 역할 분리를 기본으로 강제: survey-service의 404 재적재(spec 5절)가 깨지고 호출자 토큰 역할 이름을 이 리포가 모른다. 메커니즘만 제공하고 기본은 열어 둔다(deploy가 역할을 정하면 `PUT_ROLES`).
- 입력을 잘라서 통과: 환자 발화가 조용히 바뀌어 값이 틀린다. 거절이 낫다.

## 결과
호환 주의: 토큰·`ALLOW_FAKE` 없이 쓰던 환경(개발 compose, deploy fake 변형)은 시작 거부된다. 얻는 것: 기본이 안전. 감수하는 것: 입력 2500자 초과 발화는 거절(survey 쪽 처리 필요), 환자 발화 속 `<`+영문자가 `< `로 바뀐다.

## 되돌리는 조건
실측으로 2500이 너무 작거나 크면 조정한다. 연결·적재 한도는 부하 측정(OPEN_GAPS H4) 뒤에 조정한다.
