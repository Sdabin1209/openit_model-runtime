# ADR 0007: 출력 재시도는 최대 3회(시드만 바꿔)

## 상태
채택. 값 3의 근거는 '헤드 승인'뿐.

## 맥락
모델 출력이 스키마나 보호 규칙을 어길 수 있다. 같은 프롬프트·같은 시드를 되풀이하면 온도 0에서 결과가 같다.

## 결정
`serving_config.max_attempts` 기본 3(첫 시도 포함), 시도 k의 시드는 `기본 시드 + k`. 프롬프트는 첫 시도와 같다(검증 오류를 덧붙이지 않는다). 선택으로 `decoding.retry_temperature`(시도 1 이상). 총 시간은 ADR 0006의 요청 총 상한이 자른다.

## 왜 (따른 표준과 근거)
표준: I9의 시드 규칙(INTERFACES I9, 헤드 승인)과 프롬프트 불변(I9). 값 3: design.md 2.3 '기본값 3은 헤드가 승인했다.' 3이 2나 5보다 낫다는 측정은 **근거 기록 없음**. 최댓값 5는 design.md가 '제안, 구현하며 확정'이라고 적었다.

## 검토한 대안과 버리는 이유
- 검증 오류를 프롬프트에 덧붙여 재시도: I9가 금지(학습 분포 이탈).
- 재시도 없음: 제약 디코딩이 놓친 위반을 못 만회. 효과는 평가의 `attempts` 분포로 본다고 설계가 적었다(측정 결과 기록 없음).

## 결과
얻는 것: 일시적 위반 회복. 감수하는 것: 재시도마다 지연이 늘어 요청 총 상한(3.5s)을 쓴다. 온도 0에서는 시드가 결과를 못 바꿀 수 있다고 설계가 인정한다.

## 되돌리는 조건
평가에서 재시도 성공률이 낮거나 지연 예산을 해치면 값을 `serving_config`로 바꾼다(해시가 바뀌므로 매니페스트 재제출).
