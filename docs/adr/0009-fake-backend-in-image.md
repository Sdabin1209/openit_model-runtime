# ADR 0009: fake 백엔드를 서버 이미지에 두고 운영에서는 막는다

## 상태
채택. 운영 차단은 0.7.3에서 추가.

## 맥락
공통 규칙은 이웃 영역 없이 혼자 시험할 수 있어야 하고, 서비스 영역의 이미지가 빌드·`/healthz`를 매번 확인받도록 한다(D22). 이웃(survey-service, deploy E2E)은 GPU 없이 이 서버의 HTTP 경로를 시험해야 한다.

## 결정
같은 이미지에서 `MODEL_RUNTIME_BACKEND=fake`로 CPU 변형을 쓴다(Dockerfile `VARIANT=cpu`). 실제 vLLM 대신 결정적 출력을 내고, 흐름 파일(`order`/`slots`/`skips`/`corrections`)로 문항 흐름·값·정정을 낼 수 있다. fake는 `MODEL_RUNTIME_ALLOW_FAKE=1`이 없으면 시작을 거부한다.

## 왜 (따른 표준과 근거)
표준: 공통 규칙 D22(이웃의 메모리 구현으로 혼자 시험, 매 변경마다 이미지 확인)와 D49(영역 사이는 HTTP). 이미지를 둘로 나누지 않으면 시험한 산출물이 운영 산출물과 같다. 운영 차단의 이유: 감사(MR-1/E3)가 지적한 대로 실수로 `BACKEND=fake`가 들어가면 모델 없이 그럴듯한 응답을 내며 뜰 수 있다.

## 검토한 대안과 버리는 이유
- fake 전용 별도 이미지: 시험한 이미지와 운영 이미지가 달라진다. 별도 이미지로 할 때의 비교 기록은 없다(근거 기록 없음).
- 차단 없음: 운영 사고 위험. 기각.

## 결과
얻는 것: GPU 없는 E2E, 정정 같은 흐름 재현. 감수하는 것: fake 코드가 운영 이미지에도 들어간다(플래그로만 켜진다). deploy가 fake를 쓰려면 `ALLOW_FAKE=1`을 주어야 한다(CHANGELOG 0.7.3 호환 주의).

## 되돌리는 조건
fake를 운영 이미지에서 빼야 한다는 요구가 생기면 이미지를 나눈다.
