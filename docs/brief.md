# 영역 브리프: model-runtime (공유 라이브러리)

> **계약 상태.** 이 라이브러리는 문진 스키마만 소비하며 경계 계약에는 의존하지 않는다.
> **읽기.** `../survey-service/schema`는 문진 서비스의 데이터 스키마(스키마만 남긴 최소 구성)다. 구현이 가져가는 계약은 `schemas/<계약명>.json`(JSON Schema Draft 2020-12), 컴포넌트별 입력·출력 대응은 `COMPONENTS.yaml`, 정수 버전은 `CONTRACT_VERSION`이다. 읽기 전용이다.
> **버전(D14, D19).** 문진 스키마 정수 버전(`CONTRACT_VERSION`)에 정확히 일치해야 한다.

## 1. 목적과 범위

- 목적: 학습 후 평가, 게이트의 승인 평가, 서비스 추론이 같은 방식으로 모델을 로딩하고 같은 프롬프트·디코딩으로 호출하게 한다.
- 하는 일: LoRA 어댑터 로딩, 프롬프트 템플릿, 디코딩 설정, 출력 형식 보장(스키마 제약 디코딩 또는 검증 후 재시도, 방식은 이 리포지토리가 정한다, O14).
- 하지 않는 일: 학습, 모델 저장소 관리(model-lab), 서빙 인프라(survey-service의 추론 서버), 판단 로직(turn-engine).

## 2. 소유하는 것

- 소유 저장소: 없음.
- 제공(정확한 시그니처는 `../boundary-contracts/INTERFACES.md`의 I9가 정한다): 라이브러리 API. Parser(`UtteranceParserInput` → `ParserOutput`)와 Generator(`ResponseGeneratorInput` → `GeneratorOutput`) 호출 인터페이스, 어댑터 로딩 인터페이스. 실제 모델 없이 테스트할 수 있는 가짜 모델 구현을 함께 배포한다.
- 프롬프트 템플릿과 디코딩 설정의 버전을 모델 패키지·릴리스 매니페스트에 기록할 수 있게 한다.

## 3. 소비하는 것

- 소비하는 계약: `UtteranceParserInput`/`ParserOutput`, `ResponseGeneratorInput`/`GeneratorOutput` 및 하위 타입.
- 소비하는 SDK: 없음. 의존은 문진 스키마뿐이다.
- 지원하는 계약 버전: 문진 스키마 정수 버전 한 값.

## 3-1. 경계 명세 (블랙박스 기준)

상대 영역은 블랙박스다. 아래 인터페이스 번호의 시그니처, 오류, 멱등성은 `../boundary-contracts/INTERFACES.md`와 `CONVENTIONS.md`가 정한다. 이 명세 밖의 것을 상대에게 기대하거나 가정하지 않는다.

- 내는 것: **I9** (`load`, `ModelSession.parse/generate`, `render_prompt`, `FakeModelSession`, `RUNTIME_VERSION`).
- 받는 것: 문진 스키마의 입력 계약, 어댑터 디렉터리.
- 해야 하는 것: 출력이 스키마를 통과하지 못하면 `BackendNotAvailable 같은 인프라 예외(출력 문제는 예외가 아니라 규칙이 정한 대체 출력, D36)`. 학습 변환과 서빙이 `render_prompt`로 같은 프롬프트를 쓴다.

## 4. 상위 수용 기준

- 학습·평가·서비스에서 같은 입력이 같은 프롬프트로 조립된다.
- 출력은 항상 해당 출력 계약의 스키마를 통과하거나, 명시적 실패 신호로 끝난다. 스키마 위반을 조용히 통과시키지 않는다.
- 가짜 모델로 GPU 없이 호출 경로 전체를 시험할 수 있다.
- 어댑터와 프롬프트·디코딩 버전이 서로 어긋나면 로딩을 거부한다.

## 5. 비기능 요구

- 지연: 추론 지연의 대부분이 여기서 나온다. 수치 요구는 아직 없으며 survey-service와 정한다.
- 자원: GPU(실제 모델), CPU(가짜 모델).
- 보안·개인정보: 입력 발화를 로그로 남기지 않는다.

## 6. 건드리면 안 되는 경계

- 문진 스키마 외에 다른 리포지토리에 의존하지 않는다.
- 모델이 판단하게 만드는 프롬프트를 두지 않는다(역할 분리 원칙).

## 7. 이 영역에 해당하는 열린 결정

- O14 모델 출력 형식 보장 방식: 이 리포지토리가 정한다.
- O07 구현 언어: 권고 Python(D18).

## 8. 시드

어댑터 로딩, 프롬프트 템플릿, 디코딩·출력 형식 보장(설계서의 공유 라이브러리).

## 9. 요구하는 산출물

- `docs/design.md`, `docs/boundary.md`, 입출력 예시와 테스트, 에이전트용 `CLAUDE.md`, 변경 이력

## GPU 호스트(gpu-dev) 사용 규칙 (D47)

- 접속: `ssh -o BatchMode=yes -o ConnectTimeout=10 gpu-dev <명령>`. 작업 폴더는 호스트의 `~/openit-gpu/<리포지토리 이름>/` 하나다. 이 밖에는 읽기만 하고, 모델 내려받기용 캐시(`~/.cache`) 외에는 쓰지 않는다. `sudo`를 쓰지 않는다.
- 코드와 데이터는 이 환경에서 `rsync -a --exclude .venv --exclude .git --exclude runs <리포지토리>/ gpu-dev:openit-gpu/<이름>/`로 보낸다. 호스트에서 GitHub에 접속하지 않는다. 비밀 값(SSH 키, 웹훅 주소, 토큰, `.env`)을 호스트로 보내지 않는다. 결과는 `rsync`로 이 환경의 `runs/`(gitignore)로 가져온 뒤 이쪽에서 게시한다.
- 가상환경은 호스트의 작업 폴더 안 `.venv`에 만든다. `pip`는 호스트에 아직 없을 수 있다. 없으면 설치하지 말고 사용자에게 알려라(사용자가 `sudo apt install python3-pip python3-venv`를 한다).
- GPU는 한 장(약 12GB)이고 다른 세션도 쓴다. GPU를 쓰는 모든 명령은 `flock -w 1800 ~/openit-gpu/.gpu.lock <명령>`으로 감싸고, 오래 걸리는 것은 `timeout`을 건다.
- 서버는 항상 켜져 있지 않고 중간에 꺼질 수 있다. 긴 작업은 `setsid nohup`으로 분리해 실행하고 로그를 폴링한다. 모든 학습은 체크포인트에서 이어 실행되어야 한다. SSH가 실패하면 두 번까지만 다시 시도하고, 그래도 안 되면 하던 일을 `docs/STATUS.md`에 정리하고 멈춘 뒤 보고에 "호스트 불가"라고 적는다. 반복 재시도 루프를 만들지 않는다.
- 이 호스트는 개발용이고 실제 스테이션은 더 크다. 12GB에 맞춘 값(기반 모델, 양자화, 최대 길이, 배치, 메모리 비율)은 코드에 박지 말고 `profiles/gpu-dev-12g.*` 설정 프로파일로 둔다. 이 호스트의 학습 결과는 파이프라인 검증용이며 성능 판단 근거가 아니다. 어댑터는 기반 모델에 묶이므로 다른 기반 모델로 옮길 수 없다.
- 임시 기반 모델은 `Qwen/Qwen2.5-1.5B-Instruct`(Apache-2.0)다. 실제 기반 모델 선정은 헤드가 별도로 올린다.
